## Ноутбук 01 — Классификация (логистическая регрессия)

### Часть 1. Данные и интуиция
1. Сгенерировать датасет, отрисовать scatter: `height` vs `weight`, цвет по классу. Сразу видно — точки разделимы прямой.
2. Markdown: "наша задача — найти прямую `w1·height + w2·weight + b = 0`, которая лучше всего разделяет классы".

### Часть 2. От прямой к вероятности — сигмоида
3. Объяснить, почему линейный выход `z = w1·x1 + w2·x2 + b` плохо подходит для классификации (выходит за [0,1]).
4. Ввести сигмоиду `σ(z) = 1 / (1 + e^(−z))`. График сигмоиды.
5. Показать, что `P(y=1 | x) = σ(z)`.

### Часть 3. Функция ошибки — log-loss (cross-entropy)
6. Markdown с формулой:
   `L = −(1/n) Σ [y·log(ŷ) + (1−y)·log(1−ŷ)]`
7. **Визуализация формы лосса для одного примера**: на одном графике показать `−log(ŷ)` для `y=1` и `−log(1−ŷ)` для `y=0`. Видно, что ошибка стремится к 0 при правильном уверенном предсказании и к ∞ при уверенно неправильном.
8. **Главный график** — 3D-поверхность loss как функции от `(w1, w2)` (b фиксируем в нуле или в оптимуме). Plotly Surface + 2D contour plot матплотлибом. Минимум хорошо виден глазом.

### Часть 4. Откуда берётся "пропорциональность признаку" (ключевой раздел)
9. Markdown — вывод градиента **на бумаге**:
   - `z = w1·x1 + w2·x2 + b`
   - `ŷ = σ(z)`
   - `L = −(y·log ŷ + (1−y)·log(1−ŷ))`
   - применяем chain rule: `∂L/∂w_j = (ŷ − y) · x_j` (включая, что `1/n` появляется при усреднении по выборке)
10. Markdown-разбор: **смотри, почему именно `x_j`**. Если признак `x_j` большой — даже при той же ошибке `(ŷ−y)` обновление веса будет сильнее. Если `x_j = 0` — вес вообще не меняется. Это и есть "пропорционально влиянию признака".
11. Знак: `(ŷ−y) > 0` (предсказали больше чем надо) и `x_j > 0` → градиент положительный → антиградиент отрицательный → `w_j` уменьшаем. Аналог твоего `2x` для параболы — знак производной показывает, в какую сторону двигаться.
12. **Числовой пример "вручную"** (отдельная ячейка): берём ОДНУ конкретную точку (например `height=180, weight=95, y=1`), стартовые веса `w=[0,0], b=0`. Считаем шаг за шагом: `z=0`, `ŷ=0.5`, ошибка `(ŷ-y)=-0.5`, градиенты `[(-0.5)·180, (-0.5)·95] = [-90, -47.5]`, обновлённые веса `w_new = w - 0.001·[-90, -47.5] = [0.09, 0.0475]`. Видно физически: `w1` (вес при росте) обновился сильнее, потому что `height=180` больше чем `weight=95`. Это и есть та "магия", из-за которой признаки в разных масштабах создают перекос — мостик к разделу про скейлинг.
13. **Развенчание мифа про learning_rate**: markdown с заголовком "Что lr НЕ делает". Чётко: `lr` умножается **на градиент**, а не на ошибку. Если градиент = `[100, 0.01]`, то с `lr=0.1` обновления будут `[10, 0.001]` — никакого "20% от ошибки" нет. lr — это **размер шага** в весовом пространстве вдоль направления антиградиента.
14. **Визуализация частных производных как 1D-срезов loss**: при текущих `w` зафиксировать `w2` и нарисовать `L(w1)` как 1D-кривую с касательной в текущей точке (показывает наклон = ∂L/∂w1). Рядом — то же для `w2`. Это буквально визуализирует "знак производной → куда двигаться" на одномерных параболах, аналогично твоему примеру с `x²`.

### Часть 5. Реализация на NumPy
15. Класс `LogRegNumpy` с методами `fit(X, y, lr, n_epochs)` и `predict_proba(X)`.
    - инициализация весов нулями;
    - в цикле эпох: `z = X @ w + b`, `y_hat = sigmoid(z)`, `grad_w = (1/n) X.T @ (y_hat − y)`, `grad_b = (y_hat − y).mean()`, `w -= lr·grad_w`.
    - на каждой эпохе сохраняем: `loss`, `w`, `b`, точность.
16. Обучаем на **немасштабированных** данных. Строим:
    - график loss по эпохам;
    - график `w1`, `w2`, `b` по эпохам (видно, как веса "находят" свои значения);
    - decision boundary поверх scatter'а данных.
17. **Визуализация траектории GD на контурной карте** — на той же контурной карте лосса из Части 3 рисуем путь `(w1, w2)` по эпохам как ломаную. Это и есть тот самый "спуск в минимум".
18. **Развенчание мифа "ошибка станет нулевой"**: после обучения распечатать финальный loss и сравнить с теоретическим минимумом. Из-за шума в метках (5% мы добавили специально) и того, что точки не идеально разделимы — финальный loss > 0. Markdown: минимум функции — это точка, где ∇L = 0, но **значение** этой функции в минимуме определяется данными. Если данные шумные / неразделимые — ошибка в минимуме не ноль, и это нормально. GD ищет минимум, а не "обнуляет" ошибку.

### Часть 6. Эффект масштабирования (ключевой раздел)
19. Применяем `StandardScaler` к `(height, weight)`.
20. Перерисовываем **те же три графика рядом** (subplot 1×2):
    - loss-поверхность без / со скейлингом → видно, что у немасштабированной получается **сильно вытянутый эллипс** (потому что `weight` и `height` в разных масштабах), а у масштабированной — почти круг;
    - траектория GD без скейлинга **зигзагит** к минимуму, со скейлингом идёт почти по прямой;
    - кривая loss по эпохам — со скейлингом сходится в разы быстрее.
21. Markdown-разбор: вот почему скейлинг — не косметика, а напрямую влияет на оптимизацию. Связь с числовым примером из шага 12: там градиент по `w1` был в ~2 раза больше, чем по `w2`, ровно потому что `height > weight`. Скейлинг приводит признаки к одинаковому масштабу → градиенты одинакового масштаба → круглая loss-поверхность.
22. **Сравнить обученные веса в обоих случаях**: распечатать `w_unscaled` и `w_scaled` рядом — числа будут РАЗНЫЕ по абсолютной величине (точные значения подскажет обучение). Но если обратно преобразовать `w_scaled` в исходное пространство (по формуле `w_orig = w_scaled / σ`, `b_orig = b_scaled − Σ w_scaled · μ / σ`), то получим то же decision boundary, что и при прямом обучении на немасштабированных данных. Это снимает страх "а вдруг я скейлингом сломал интерпретацию": скейлинг — это просто смена системы координат, физика та же.

### Часть 7. Эффект learning rate
23. Подобрать 3 значения lr (слишком маленький / нормальный / слишком большой). Показать на одном графике три кривых loss. Объяснить расходимость при большом lr (перепрыгиваем минимум, loss растёт). На контурной карте — три траектории: маленький lr (мелкие шажки, не дошли), нормальный (плавно в минимум), большой (зигзагом в обратную сторону).

### Часть 8. Сравнение с sklearn
24. Обучить `sklearn.linear_model.LogisticRegression(penalty=None)` (отключаем регуляризацию для честного сравнения). Сравнить веса и accuracy — должны почти совпасть. Это валидация: "наша numpy-реализация не игрушечная, она делает ровно то же, что и production-код".

## Ноутбук 02 — Регрессия (линейная регрессия)

Та же логика, но проще: лосс — MSE (выпуклый параболоид), нет сигмоиды.

### План:
1. Сгенерировать датасет квартир. Scatter `area` vs `price`, `dist` vs `price`, 3D scatter `(area, dist, price)`.
2. Идея модели: `price = w1·area + w2·dist + b`. Хотим найти `w1, w2, b`.
3. **MSE как функция ошибки**: `L = (1/n) Σ (ŷ − y)²`. Markdown — почему именно квадрат (штраф за большие ошибки, гладкость, выпуклость).
4. **3D-визуализация loss(w1, w2)** при фиксированном b (или b в оптимуме) — Plotly Surface. Видно идеальный параболоид с одним минимумом.
5. **Вывод градиента на бумаге** — снова получаем `∂L/∂w_j = (2/n) Σ (ŷ − y)·x_j`. Подсветить: **то же самое `x_j`, та же логика**, что и в логистической. Это объединяющая идея.
6. Реализация `LinRegNumpy` на numpy с тем же интерфейсом.
7. Обучение **без скейлинга** — **с подвохом**: на этом датасете `price ~ десятки тысяч, area ~ десятки` → градиенты порядка `10⁷` → с обычным lr (например 0.01) GD немедленно расходится (loss взрывается). Markdown: "смотри, что произошло — `lr` слишком велик для масштаба градиентов, шаги перепрыгивают минимум". Подобрать очень маленький lr (≈ `1e-7`) → GD сходится, но **очень медленно**, через тысячи эпох. Показать график loss и финальные веса.
8. Сравнить обученные `(w1, w2, b)` с истинными `(1500, −800, 50000)` — после долгого обучения должны совпасть с точностью до шума. **Это важный момент**: подтверждение, что метод реально находит скрытые коэффициенты.
9. **Со скейлингом** — обучение работает на нормальном lr (0.01) и сходится за десятки эпох. Side-by-side: loss-поверхность (вытянутый эллипс vs круг), траектория GD, кривая loss. Показать, насколько драматическая разница: со скейлингом то же самое решение получается в 100+ раз быстрее.
10. Эффект learning rate (3 значения, на масштабированных данных, чтобы было корректно).
11. Сравнение с `sklearn.linear_model.LinearRegression`. Также упомянуть **аналитическое решение** `w = (X^T X)^(-1) X^T y` (нормальное уравнение) — для линейной регрессии минимум вообще можно найти без GD за один шаг матричной алгебры. Это ответ на вопрос "почему мы знаем, что в этой точке минимум" — потому что для линейной регрессии минимум **выводится формулой**; GD — лишь итеративный способ к нему прийти, который пригодится, когда формулы нет (как в нейросетях).
12. Раздел "интерпретация коэффициентов":
    - в исходных единицах: `w1 = 1500` значит "+1 м² → +1500 руб.";
    - после скейлинга: `w_scaled,1 = w_orig,1 · σ_area` (для нашего датасета `σ_area ≈ 36`, значит `w_scaled,1 ≈ 54000`), то есть "+1 std площади (~36 м²) → +54000 руб.";
    - вывод: интерпретация не "ломается", а просто меняет единицу измерения признака (с "метров квадратных" на "стандартных отклонений"). Численные значения подскажет обучение.

### Часть 7. "Что значит интерпретируемость" (резюме)
18. Markdown-таблица "что мы можем сказать про предсказание для каждой модели":

    - **Bagging**: то же что RF по интерпретации, но без рандомизации признаков на split'ах.
    - **Gradient Boosting**: `feature_importances_` есть, но дополнительно можно использовать SHAP/partial dependence (упомянуть, не реализовывать).
    - **Stacking**: коэффициенты мета-модели = "степень доверия" к каждому базовому алгоритму.
19. Markdown-вывод: чем сложнее модель, тем выше потенциальная точность, но тем сложнее объяснить КОНКРЕТНОЕ предсказание. Это фундаментальный trade-off, который надо понимать на проекте.

## Что осознанно НЕ включаю

- регуляризация (L1/L2) — отдельная большая тема, добавлять только если попросят;
- многоклассовая классификация — задача "худой/толстый" бинарная, для интуиции этого хватает;
- кросс-валидация — она уже разобрана в существующих лабах, здесь фокус на интуицию обучения, а не на оценку качества;
- ROC/AUC — тоже разобрано в существующих лабах;
- работа с GTZAN — синтетические 2D-датасеты намеренно проще, чтобы можно было всё нарисовать в плоскости.
