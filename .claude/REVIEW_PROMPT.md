## Процесс для КАЖДОЙ лабы N

### Шаг 1 — Загрузи задание

Прочитай задание из `машинное обучение/машинное обучение/` (папка по CLAUDE.md).
Выпиши ВСЕ конкретные требования как нумерованный чек-лист.

### Шаг 2 — Прочитай ноутбук

Прочитай `lab{N}/lab{N}.ipynb` целиком (через Read tool).
Если есть `lab{N}/PLAN.md` — тоже прочитай.
Зафиксируй:
- Сколько code-ячеек и все ли выполнены (есть execution_count)
- Есть ли ошибки в output
- Сколько визуализаций (plt.show / fig.show)
- Есть ли теоретическое введение
- Есть ли выводы

### Шаг 3 — Оценка по 7 критериям

Оцени ноутбук по шкале 0-10 для каждого критерия:

| Критерий | Вес | Что проверяем |
|----------|-----|---------------|
| **Покрытие задания** | 25% | Каждое требование из задания (Шаг 1) реализовано в ноутбуке |
| **Корректность кода** | 20% | Все ячейки выполнены, нет ошибок, корректные вызовы API |
| **Теория** | 15% | Раздел «Теоретическое введение» ≥3 абзацев, формулы если уместно |
| **Визуализации** | 15% | ≥3 графиков с подписями осей, заголовками и интерпретацией |
| **Выводы** | 10% | Раздел «Выводы», итоги работы, практическое значение |
| **Структура** | 10% | PLAN.md есть, markdown перед каждым блоком кода, русский язык |
| **Качество кода** | 5% | Чистые импорты, нет дубликатов, понятные имена переменных |

**Взвешенная оценка** = Σ(оценка_i × вес_i × 10). Максимум = 100.

### Шаг 4 — Решение

Think hard. Определи статус:

- **PASS** — если оценка ≥ 80 И каждый критерий ≥ 5. Переходи к Шагу 7.
- **NEEDS_FIX** — если оценка < 80 ИЛИ хоть один критерий < 5. Составь план исправлений и переходи к Шагу 5.

**Важно:** исправления вносим только если они **существенно** улучшат качество. Не трогай то, что уже работает нормально. Минимально необходимые правки.

### Шаг 5 — Исправления

Применяй исправления по категориям:

| Проблема | Исправление |
|----------|-------------|
| Нет PLAN.md | Сгенерировать из содержимого ноутбука (как в lab4/PLAN.md) |
| Невыполненные ячейки | Перезапустить весь ноутбук: `jupyter nbconvert --execute` |
| Нет теории | Вставить markdown-ячейку «Теоретическое введение» после заголовка |
| Нет выводов | Добавить markdown-ячейку «Выводы» в конец |
| Мало визуализаций (<3) | Добавить графики (по смыслу лабы) |
| Ошибки кода | Исправить код и перезапустить ноутбук |
| Нет markdown перед кодом | Добавить поясняющие markdown-ячейки |

**После правок** обязательно перезапусти ноутбук:
```bash
source /home/ilya/venvs/psu-ml/bin/activate && jupyter nbconvert --to notebook --execute lab{N}/lab{N}.ipynb --output lab{N}.ipynb --ExecutePreprocessor.timeout=300
```

**Валидация после исправлений** — убедись:
- Все code-ячейки выполнены
- Нет ошибок в output
- Визуализации рендерятся

**Стратегия обработки ошибок:**
- Максимум 3 попытки исправления на один ноутбук
- Если ноутбук не запускается после 3 попыток — пометь как проблемный, двигайся дальше
- Используй context7 MCP при ошибках API библиотек
