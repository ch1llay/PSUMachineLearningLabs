# /init-lab-repo — Инициализация репозитория для автономного выполнения лабораторных

Ты архитектор инфраструктуры для автономного выполнения университетских лабораторных работ.
Твоя задача — настроить полную систему автономной работы в текущем репозитории.

Аргументы пользователя: $ARGUMENTS

## Что ты создашь

В текущем репозитории будут созданы:
1. `CLAUDE.md` — инструкции для Claude Code
2. `.claude/AUTORUN_PROMPT.md` — промт автономного выполнения лаб
3. `.claude/REVIEW_PROMPT.md` — промт автономной проверки лаб
4. `.claude/DIAGNOSTICS_PROMPT.md` — промт диагностики окружения
5. `.claude/progress.json` — файл прогресса (state machine)
6. `.claude/settings.json` — настройки разрешений и хуков
7. `.claude/hooks/stop.sh` — хук автопродвижения между лабами
8. `.mcp.json` — конфигурация MCP серверов
9. `README.md` — README с таблицей прогресса

## Референс

Шаблоны: `init-lab-perform/templates/`

При сомнениях читай соответствующий шаблон для контекста.

## Фаза 1 — Discovery

Исследуй текущий репозиторий:

1. **Git**: Проверь `git status`. Если не git-репозиторий — спроси пользователя, нужно ли `git init`.
2. **Задания**: Ищи файлы заданий — `.ipynb`, `.pdf`, `.md`, `.docx` в подпапках. Ищи папки с русскими/английскими названиями, нумерованные (1., 2., Lab1, LW1 и т.д.).
3. **Примеры**: Ищи папки `examples/`, `примеры/`, или любые директории с примерами одногруппников.
4. **Датасеты**: Ищи `datasets/`, `data/`, файлы `.csv`, `.xlsx` в корне и подпапках.
5. **Существующая конфигурация**: Проверь наличие `.claude/`, `CLAUDE.md`. Предупреди если будет перезапись.

Покажи пользователю результаты сканирования, затем переходи к Фазе 2.

---

## Фаза 2 — Interview

Собери ВСЮ необходимую информацию через AskUserQuestion. Задавай вопросы группами (2-4 за раз), не всё сразу.

### Группа 1 — Основное

Используй AskUserQuestion, чтобы узнать:
- **Название предмета** (например, "Глубокое обучение", "Цифровая обработка изображений")
- **Краткий код** для путей и токенов (например, "dl", "dip", "ml")
- **Роль эксперта** на русском (например, "Senior Python DL разработчик/исследователь")

### Группа 2 — Окружение

- **Путь к venv** (предложи дефолт: `/home/ilya/venvs/psu-{код}/`)
- **Основные библиотеки** через запятую (предложи на основе предмета)
- **JupyterLab URL** (дефолт: `http://localhost:8888`) и **токен** (дефолт: `psu-{код}-token`)

### Группа 3 — Лабораторные

- **Номера лаб**: какие существуют (например, "1-12" или "1-7, 9-16")
- **Темы лаб**: для каждого номера — краткое название темы
- **Уже выполненные**: какие лабы уже сделаны (дефолт: нет)
- **Путь к заданиям**: подтверди найденные при Discovery или спроси

### Группа 4 — Условные (задавай только если релевантно)

Если при Discovery найдены **примеры**:
- Подтверди что это примеры одногруппников
- Спроси паттерны имён файлов для каждого источника
- Спроси путь к каждому источнику

Если при Discovery найден **датасет**:
- Подтверди что это основной датасет
- Спроси краткое описание (строки, столбцы, целевая переменная)

Если датасет НЕ найден:
- Спроси: "Каждая лаба использует свой датасет, или общего датасета нет?"

Опционально спроси:
- Предметно-специфические соглашения (например, "всегда показывать архитектуру модели")
- Язык markdown ячеек (дефолт: русский)

## Фаза 3 — Generation

После сбора всех ответов генерируй файлы. Для каждого файла:
1. Прочитай соответствующий шаблон из `init-lab-perform/templates/`
2. Замени все `{{PLACEHOLDER}}` на собранные значения
3. Обработай условные секции:
   - `{{#IF HAS_EXAMPLES}}...{{/IF}}` — включи только если есть примеры
   - `{{#IF NO_EXAMPLES}}...{{/IF}}` — включи только если примеров НЕТ
   - `{{#IF HAS_DATASET}}...{{/IF}}` — включи только если есть общий датасет
   - `{{#IF HAS_ASSIGNMENTS_DIR}}...{{/IF}}` — включи только если задания в отдельной папке
   - `{{#IF HAS_MULTIPLE_EXAMPLES}}...{{/IF}}` — включи если >1 источник примеров
4. Удали оставшиеся теги `{{#IF...}}` и `{{/IF}}` из финального текста
5. Запиши файл

### Порядок генерации

```
mkdir -p .claude/hooks
```

1. **`.claude/progress.json`** — заполни FIRST_LAB, COMPLETED_LABS
2. **`.claude/settings.json`** — заполни VENV_PATH
3. **`.claude/hooks/stop.sh`** — заполни LAB_NUMBERS, FIRST_LAB, MAX_LAB, затем `chmod +x`
4. **`.mcp.json`** — заполни VENV_PATH, JUPYTER_URL, JUPYTER_TOKEN
5. **`.claude/AUTORUN_PROMPT.md`** — самый сложный файл, внимательно обработай условные секции
6. **`.claude/REVIEW_PROMPT.md`** — заполни веса критериев (дефолт: 25/20/15/15/10/10/5)
7. **`.claude/DIAGNOSTICS_PROMPT.md`** — адаптируй номера шагов, заполни условные проверки
8. **`CLAUDE.md`** — собери все секции, обработай условные блоки
9. **`README.md`** — таблица лаб со статусами

## Фаза 4 — Validation

После генерации всех файлов:

1. Проверь что все 9 файлов существуют
2. Проверь что `.claude/progress.json` — валидный JSON
3. Проверь что `.claude/settings.json` — валидный JSON
4. Проверь что `.mcp.json` — валидный JSON
5. Проверь что `.claude/hooks/stop.sh` исполняемый
6. Покажи пользователю сводку созданных файлов

Предложи пользователю:
- Запустить `/diagnostics` для полной проверки окружения
- Запустить автономное выполнение: вставить текст из `.claude/AUTORUN_PROMPT.md`
- Запустить ревью: изменить mode в progress.json и вставить текст из `.claude/REVIEW_PROMPT.md`

---

## Важные правила

- НЕ спрашивай всё за один раз — группируй по 2-4 вопроса
- Используй AskUserQuestion для структурированных вопросов с вариантами
- Если пользователь передал аргументы ($ARGUMENTS) — используй их для ускорения (пропусти уже известное)
- Предлагай разумные дефолты на основе названия предмета
- При ошибках в шаблонах — сгенерируй контент самостоятельно по образцу из шаблонов
- Все сгенерированные промты должны быть на русском языке
- Финальные файлы НЕ должны содержать `{{...}}` плейсхолдеры — всё должно быть заполнено
